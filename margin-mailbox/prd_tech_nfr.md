## 1. 비기능 요구사항 (Non-Functional Requirements)

### 1.1 모바일 최적화 및 반응형 디자인 (Mobile-First & Responsive UI) — [최우선 강조]
* **모바일 완벽 지원:** 본 서비스는 사용자가 잠들기 전 침대 위나 이동 중 스마트폰으로 다이어리처럼 가장 빈번하게 접속하는 서비스이므로, **모바일 환경(iOS Safari, Android Chrome / 뷰포트 `360px~430px`)에서 모든 화면과 기능이 깨짐 없이 완벽하게 동작**해야 한다.
* **모바일 UX 디테일:**
  * 가상 키보드(Virtual Keyboard)가 올라올 때 감정 체크인 입력창이나 시 에디터의 작성 영역 및 제출 버튼이 가려지지 않도록 동적 뷰포트(`dvh`) 대응을 적용한다.
  * 한 손 조작이 편하도록 주요 버튼(편지 열기, 글쓰기 전환, 저장)의 터치 영역(최소 `44x44px`)과 하단 배치 간격을 충분히 확보한다.
  * 모바일 브라우저에서 가로 스크롤이 절대 발생하지 않으며, 태블릿(`768px`) 및 데스크톱(`1280px` 이상) 환경에서도 여백의 미가 살아나는 반응형 레이아웃을 제공한다.

### 1.2 보안 및 프라이버시 (Security & Privacy)
* **데이터 접근 제어 (RLS):** Supabase의 Row Level Security(RLS)를 엄격히 적용하여, `is_public = false`(비공개)로 설정된 게시글과 감정 체크인 원문은 오직 작성자 본인(`auth.uid()`)만 조회 가능하도록 DB 레벨에서 차단한다.
* **관리자 권한 이중 검증:** 클라이언트 UI 숨김 처리뿐만 아니라, Next.js 서버 액션/API 라우트 및 Supabase RLS 레벨에서도 지정된 관리자 이메일(`auth.jwt() ->> 'email'`)인지 이중으로 검증한다.
* **익명성 보장:** 타인에게 편지가 배달될 때 작성자의 실명이나 개인정보 대신 필명(닉네임)만 노출한다.

### 1.3 성능 (Performance)
* **응답 속도:** 페이지 초기 로딩 시간(LCP)은 2.5초 이내여야 하며, AI 감정 분석 및 편지 매칭 API 응답은 스트리밍(Streaming) 또는 로딩 애니메이션과 함께 3~4초 이내에 완료되어야 한다.
* **체류 시간 최적화 UX:** 무한 스크롤을 구현하지 않으며, 하루 1~2편 열람 후 글쓰기로 이어지는 선형적(Linear) 네비게이션 구조를 유지한다.

### 1.4 접근성 및 가독성 (Accessibility & Readability)
* 시 감상에 방해가 되지 않는 따뜻한 종이 질감의 배경색, 높은 명도 대비(WCAG AA 기준 충족), 모바일 작은 화면에서도 행간과 자간이 편안한 세리프(명조) 계열 웹폰트를 적용한다.

## 2. 기술 제약 사항 (Technical Constraints)

본 프로젝트는 **1인 또는 소규모 개발 환경에서 초기 비용 0원(Free Tier) 또는 최소 비용으로 즉시 배포 및 운영**이 가능해야 한다.

* **프론트엔드 & 호스팅:** **Vercel**
  * Next.js App Router 기반 풀스택 웹 애플리케이션 배포 (무료 Hobby 플랜 활용)
* **백엔드, 인증 & 데이터베이스:** **Supabase**
  * PostgreSQL DB, Supabase Auth 이메일/소셜 로그인, RLS 보안 정책 (무료 Free 플랜 활용)
* **AI 엔진:** **Gemini AI (`gemini-2.5-flash` 모델 권장)**
  * **도메인 가드레일 프롬프트 적용:** 시스템 프롬프트(System Instruction)에 입력 의도 분류(Intent Classification) 로직을 포함하여, 감정·문학 외의 무관한 질문일 경우 즉시 지정된 거절 안내 문구(`prd_features.md` 기능 1 참조)를 반환하도록 설계한다.
  * **비용 최적화 전략:** 입력 토큰이 짧은 텍스트(감정 체크인 및 시 1편) 분석에 특화된 경량 모델(`gemini-2.5-flash`)과 JSON Structured Outputs를 사용하여 API 호출 비용과 지연 시간을 최소화한다.
  * **하루 1회 제한 캐싱:** 동일한 사용자가 하루에 여러 번 접속하더라도 불필요한 AI 재호출을 줄이기 위해 당일 감정 체크인 및 추천 편지 목록(1~2개)을 DB(`daily_deliveries` 테이블)에 저장(캐싱)하여 재사용한다.
